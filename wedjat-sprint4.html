1. Objetivo e escopo

O Wedjat apoia pré-vendas e vendas TOTVS com oportunidades comerciais, transcrições de reunião, metodologia SPICED, score de handoff e dashboard por BU. Na Sprint 4, a solução evoluiu de menu console para API REST (Javalin) consumida por um front-end web, mantendo domínio, serviços e DAOs JDBC sobre Oracle FIAP.

2. Funcionalidades principais

  • Cadastro, listagem, edição e exclusão de oportunidades (CRUD com validação).
  • Registro de transcrição com extração automática de insights.
  • Atualização SPICED, briefing com lacunas e perguntas sugeridas.
  • Cálculo e persistência do handoff score (0–100).
  • Dashboard consolidado e filtro por unidade de negócio.

4. Telas implementadas (prints)

Front estático em web/ (Oportunidades, Reunião, SPICED, Handoff, Dashboard), servido pela mesma API na porta 7070.

4.1 Oportunidades — cadastro e pipeline

Demais telas: abas Reunião (transcrição + insights), SPICED (campos + briefing), Handoff (score) e Dashboard (cards e barras). Capturar prints adicionais com a API em execução, se o professor solicitar mais imagens.

5. Modelo do banco de dados

Oracle FIAP — 5 tabelas: TB_OPPORTUNITY, TB_SPICED_ASSESSMENT, TB_MEETING_RECORD, TB_INSIGHT, TB_HANDOFF_SCORE. DDL em sql/ddl.sql (Sprint 3). Relacionamentos 1:1 (SPICED, handoff), 1:N (reuniões, insights) com ON DELETE CASCADE.

6. Diagrama de classes (atualizado)

6.1 Camada API — com.totvs.wedjat.api

ApiServer — expõe rotas Javalin, trata exceções HTTP, serve arquivos estáticos web/.
JsonView — converte entidades de domínio em JSON (evita ciclo HandoffScore ↔ Opportunity).

6.2 Camadas existentes (Sprint 3 + evolução)

WedjatSystem (application) — fachada usada pelo console e pela API.
OpportunityServiceImpl — CRUD, validação, listarResumo() para listagens rápidas.

Domínio, demais services e DAOs permanecem conforme Sprint 3 (SPICED, transcrição, handoff, dashboard).
